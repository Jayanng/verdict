# Web app

Landing page and app for Verdict, the Ootle jury court. Static site, no build
step, no wallet, no funds.

## Run it

```sh
npm run serve   # serves web/ on http://localhost:8000
```

Open http://localhost:8000/index.html. Pages are hash routed: `#/` home,
`#/app` disputes, `#/dispute/0` dispute detail and proof page, `#/open`
guided four-step dispute form, `#/juror` become a juror.

## What is built

- Home: the one-liner, the trust story, the eight invariants in plain
  language, the honest-limits copy, the "Why only Tari" section with one
  sentence and a proof link per Ootle feature, How it works, and FAQ.
- App: the disputes list, each row opening its proof page.
- Dispute detail and proof page: draw inputs with a recompute button,
  per-item evidence hash checks, panel, commits, reveals, ruling, and the
  escrow's caller rule. Three live tamper checks run in the browser against
  the published inputs: change one draw input and watch the panel change,
  change one byte of evidence and watch the hash check fail, call
  `execute_ruling` as a stranger and watch the caller rule refuse.
- Open a dispute: a guided four-step form (deal, parties, evidence, review)
  that builds a local draft in the browser and hashes each evidence item as
  it is added.
- Become a juror: bond floor 30,000 micro-Tari, fee 5,000 micro-Tari per
  dispute, risks, and the demo pool seeded with known testers and disclosed.

The proof page mirrors the template rules as they stand in
`templates/verdict/src/lib.rs`: panel derivation from draw hash, dispute id,
round, and frozen pool; commitment hash of (vote, salt, dispute id, juror);
`execute_ruling(dispute_id, payee_amount)` gated by the caller-component
rule plus the in-method assert plus `OwnerRule::None`. The shared rules live
in `src/verdict.js` and are imported by both the page and the tests.

## Sample data

Everything the app shows is sample data, labelled on every page. The three
sample disputes, the seven sample jurors, and every hash are generated by
`tools/generate-sample-data.mjs` from the template rules, so the proof checks
pass on the sample inputs. Regenerate after any rule change, do not edit
`src/sample-data.js` by hand:

```sh
npm run sample
```

No key is a real person, no hash is on chain, and no amount moved.

## Tests

```sh
npm test   # node --test tests/verdict.test.js, 18 tests
```

The suite checks the panel derivation, the vote commitment bytes, the pure
JavaScript SHA-256 against node:crypto vectors, majority and split math, the
caller rule, and that the sample data is internally consistent. These are
logic tests for the proof page, not parity tests.

## Design

NutCheck design language: floating white pill navbar, warm paper `#F6F4EF`,
electric blue `#0018FF`, white cards, near-black ink, letter cards with blue
squares, bold sans headings, checkmark ticker strip. `styles.css` holds the
brand tokens and page layout. `rare-ui.css` holds the component styles only,
kept separate per the isolation rule.

Note on the UI library: Rare UI (https://rareui.com) is a copy-paste React
component registry, not a published stylesheet, so no Rare UI code is vendored
in this static build. The footer carries the attribution link the Rare UI
license asks for. Adopting Rare UI components is a defined follow-up for the
move to React, via the shadcn CLI.

## Not in this part

- The live path via Sapient (reading the live Esmeralda indexer and
  template) is out of scope. The live path is blocked: no tTARI in hand, no
  wallet account, no wallet daemon running, hello template publish not
  attempted. The proof page works with published inputs the user can paste
  or that the sample data provides, and labels what is live versus sample.
- The full walletless simulation engine and the parity test suite wait for
  Phase 3, because the simulation must mirror the template rule for rule and
  Phase 3 is rewriting the settlement matrix. No simulation stub is shipped,
  and nothing here is counted as a parity test.
- The settlement routing shown on settled disputes is the routing as it
  stands in the templates at this commit. How juror fees are funded from the
  principal is set by the settlement matrix, which is being written now.
